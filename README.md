# BTU AI Skills Digital Passport

Business and Technology University-ის (BTU) ჰაკათონის **MVP**: სისტემა, რომელიც სტუდენტების AI Skills Digital Passport-ს ავტომატურად აგენერირებს Google Sheet-ის მონაცემებიდან, ანახლებს ვერსიებად და თითოეულ გაცემულ ვერსიას ბლოკჩეინზე ადასტურებს.

> ყველა სტუდენტი, ელფოსტა, Passport ID და ტრანზაქცია სატესტოა (BTU-ის მიერ მოწოდებული ჰაკათონის მონაცემები).

## გაშვება

ინტერნეტი საჭიროა (SQL ბიბლიოთეკა `sql.js` CDN-იდან იტვირთება).

```bash
npx serve .          # ან: python3 -m http.server 8000
```

შემდეგ ბრაუზერში გახსენით `http://localhost:3000` (ან `:8000`). `index.html`-ის პირდაპირ გახსნაც მუშაობს, მაგრამ პასპორტის გვერდების ჩვენება მაშინ ბრაუზერის PDF ხედვით ხდება.

პირველი გაშვებისას სისტემა Sheet-ში უკვე `SYNCED` ჩანაწერებიდან აღადგენს V1 ვერსიებს (8 სტუდენტი), დანარჩენი 44 ჩანაწერი კი `NOT SYNCED` სტატუსით ელოდება სინქრონიზაციას. თავიდან დასაწყებად (ადმინისტრატორით შესვლის შემდეგ): **ადმინისტრირება → წყაროს პარამეტრები → დემოს თავიდან დაწყება**.

## გვერდები

- **მთავარი:** მისასალმებელი გვერდი: სტატისტიკა, როგორ იზრდება პასპორტი, სამი ტიპის შტამპი და ვისთვისაა სისტემა.
- **ვერიფიკაცია**, **ბლოკჩეინი:** საჯარო.
- **ჩემი პასპორტი:** სტუდენტი. **ადმინისტრირება:** ადმინისტრატორი.

## არქიტექტურა

```
Google Sheet "Passport Skill Records" (A–T)        ← ადმინი ამატებს დადასტურებულ უნარს
        │  Apps Script Web App (apps-script/Code.gs)
        ▼
SQL ბაზა (SQLite / sql.js)                          ← სისტემის საკუთარი მონაცემები
  SELECT * FROM sheet_rows WHERE sync_status IN ('NOT SYNCED','FAILED')
        │
        ▼
პასპორტის ახალი ვერსია → PDF BTU-ის შაბლონში (pdf-lib, assets/passport-template.pdf)
        │  SHA-256(PDF) + BTU-ის ციფრული ხელმოწერა (ECDSA P-256)
        ▼
ბლოკჩეინი: ISSUE_PASSPORT_VERSION ბლოკი           ← პროტოტიპში სიმულირებული, საწარმოოში contracts/PassportRegistry.sol
        │
        ▼
Sheet-ში უკან ჩაიწერება G, H (ახალი პასპორტისთვის) და Q–T (SYNCED, ვერსია, დრო, შეცდომა)
```

### SQL ბაზის ცხრილები

| ცხრილი | შინაარსი |
|---|---|
| `sheet_rows` | Google Sheet-ის A–T სვეტების ასლი ყოველი სინქრონიზაციისას (staging) |
| `students`, `skills` | სტუდენტები და უნარების კატალოგი (SKL-001 … SKL-016) |
| `passports` | ერთი პასპორტი სტუდენტზე: მუდმივი Passport ID, სახელი, გვარი, პირველი გაცემის თარიღი |
| `passport_skills` | პასპორტში დამატებული უნარები (Record ID → რომელ ვერსიაში დაემატა) |
| `passport_versions` | V1, V2, …: ვერიფიკაციის კოდი, PDF-ის SHA-256, ხელმოწერა, ბლოკი, სტატუსი LATEST/SUPERSEDED |
| `ledger` | ბლოკჩეინის ბლოკები (prev_hash → block_hash ჯაჭვი) |
| `sync_runs` | სინქრონიზაციის ისტორია და შესრულებული SQL მოთხოვნები |

## ღონისძიების შედეგების ატვირთვა (Excel)

ჰაკათონის, ვორქშოფის ან კურსის შემდეგ ადმინისტრატორი ტვირთავს Excel-ს მხოლოდ წარმატებით დასრულებულ სტუდენტებით: **ადმინისტრირება → შედეგების ატვირთვა (Excel)**.

1. აირჩიეთ უნარი (Skill) და მიღების თარიღი.
2. ატვირთეთ `.xlsx` ან `.csv`. სვეტები: `First Name`, `Last Name`, `Email` (ან `სახელი`, `გვარი`, `ელფოსტა`). ახალი სტუდენტისთვის ასევე `Program` და `Education Level`. თუ ფაილში არის `Skill ID` ან `Date Earned` სვეტი, სტრიქონისთვის ის გამოიყენება.
3. სისტემა აჩვენებს თითოეულ სტრიქონს: **ემატება უნარი** / **ახალი სტუდენტი + უნარი** / **უკვე აქვს** / **ფაილში მეორდება** / **შეცდომა** (მიზეზით).
4. **Sheet-ში დამატება და სინქრონიზაცია**: ახალი სტრიქონები ემატება Google Sheet-ში (`NOT SYNCED`), სინქრონიზაცია მაშინვე ეშვება და პასპორტები ახლდება ან იქმნება.

**ახალი სტუდენტების რეგისტრაცია:** თუ უნარი არ არის არჩეული და ფაილში Skill ID სვეტი არ არის, ფაილი ჩაირიცხულთა სიად ითვლება (First Name, Last Name, Email). თითოეულ ახალ სტუდენტს Sheet-ში ემატება `ENR-…` სტრიქონი უნარის სვეტების გარეშე და ექმნება ცარიელი პასპორტი (V1, მუდმივი Passport ID, ბლოკჩეინზე რეგისტრირებული). უნარები შემდეგ ემატება ჩვეულებრივად, V2, V3… ნიმუში: `data/sample-new-students-10.xlsx`.

ნიმუშები: `data/sample-workshop-results.xlsx` · `data/sample-test-3-students.xlsx` (3 ახალი სტუდენტი, თითოს 3 უნარი) (სხვადასხვა შემთხვევით) და `data/sample-hackathon-results.xlsx` (Skill ID და Date Earned სვეტებით). Excel ბრაუზერში იკითხება გარე ბიბლიოთეკის გარეშე (`js/xlsx-read.js`).

## რეალური Google Sheet-ის დაკავშირება

1. ატვირთეთ `data/BTU_AI_Skills_Digital_Passport_Hackathon_Test_Data.xlsx` Google Drive-ში და გახსენით Google Sheets-ით.
2. **Extensions → Apps Script**, ჩასვით `apps-script/Code.gs`, შეინახეთ.
3. **Deploy → New deployment → Web app**: Execute as **Me**, Who has access **Anyone** → Deploy, დააკოპირეთ `/exec` მისამართი.
4. საიტზე: **ადმინისტრირება → წყაროს პარამეტრები → რეალური Google Sheet**, ჩასვით მისამართი → შენახვა.
5. Sheet-ში დაამატეთ ახალი სტრიქონი სტატუსით `NOT SYNCED` და საიტზე დააჭირეთ **სინქრონიზაციას**.

Q–T სვეტები სისტემის მართვაშია: ცოცხალ Sheet-ში დაიცავით ისინი ხელით რედაქტირებისგან (Data → Protect range).

## ბლოკჩეინი

პროტოტიპში ბლოკჩეინი ბრაუზერშია სიმულირებული: SHA-256 ბლოკების ჯაჭვი BTU-ის ხელმოწერით. საწარმოო ვერსიისთვის მზადაა `contracts/PassportRegistry.sol` (Polygon Amoy):

1. [remix.ethereum.org](https://remix.ethereum.org) → ჩასვით კონტრაქტი → Compile (0.8.24+).
2. MetaMask-ში Polygon Amoy ქსელი და faucet-იდან ტესტ-POL.
3. Deploy (Injected Provider). Deploy-ის მისამართი BTU-ის issuer მისამართია.
4. ყოველ გაცემაზე: `issue(docHash, keccak256(passportId), version)`, შემოწმება: `verify(docHash)`.

On-chain არ ინახება პერსონალური მონაცემები: მხოლოდ PDF-ის hash, Passport ID-ის hash და ვერსიის ნომერი.
